# 白格美宿内容方案生成器 v0.1 产品需求文档

## 1. 项目名称

白格美宿内容方案生成器 v0.1

---

## 2. 项目背景

白格美宿是一家位于河南省洛阳市栾川县重渡沟景区附近的民宿。  
目前民宿经营中存在一个现实问题：日常内容发布不稳定，不知道每天该发什么，也不知道如何把民宿的真实卖点转化成适合抖音、小红书、朋友圈发布的内容。

对于小型民宿来说，内容运营非常重要。游客在出行前通常会通过短视频、小红书、朋友圈等渠道了解住宿环境、周边景点、停车情况、亲子体验、饭菜、卫生条件等信息。

但白格美宿目前缺少一个简单工具，帮助经营者快速生成可执行的内容方案。因此，本项目希望通过 AI 辅助家人完成内容选题、标题、脚本、镜头清单和朋友圈文案的生成，降低内容创作门槛，提高日常宣传效率。

---

## 3. 项目目标

本项目第一版目标不是做一个复杂系统，而是先完成一个可以真实使用的小工具。

核心目标是：

1. 帮助白格美宿快速生成适合发布的内容方案；
2. 降低家人不知道发什么、不知道怎么拍、不知道怎么写文案的问题；
3. 让我熟悉一个完整 AI 应用项目的基本流程；
4. 完成从需求分析、页面开发、AI 调用到部署上线的完整闭环；
5. 为后续加入内容记录、数据复盘和经营建议功能打基础。

---

## 4. 目标用户

本工具的目标用户主要是：

1. 白格美宿经营者；
2. 白格美宿家人；
3. 负责发布抖音、小红书、朋友圈内容的人；
4. 未来可扩展到其他小型民宿、小商家、农家乐经营者。

---

## 5. 核心痛点

### 5.1 不知道每天发什么

民宿经营者知道自家有很多卖点，比如环境、房间、饭菜、停车、离景区近等，但不知道如何把这些卖点转化成具体内容。

### 5.2 不知道怎么写标题和文案

短视频和小红书内容需要标题吸引人，但小商家往往不会写有吸引力但又不夸张的标题。

### 5.3 不知道怎么拍视频

很多时候家人即使知道要发视频，也不知道具体拍哪些镜头，容易只拍房间或者门口，内容单调。

### 5.4 内容发布不稳定

因为选题和文案都需要临时想，所以容易三天打鱼两天晒网，导致内容运营无法持续。

### 5.5 内容没有围绕真实经营目标

有时内容可能看起来热闹，但没有真正服务于游客关心的问题，例如停车、带孩子方便、带父母舒适、离景区距离、吃饭是否方便等。

---

## 6. 第一版功能范围

白格美宿内容方案生成器 v0.1 第一版只做一个核心功能：

> 输入客群、卖点、热点、平台，自动生成一套可用于发布的内容方案。

第一版不做复杂功能，例如：

1. 暂时不做登录注册；
2. 暂时不做数据库保存；
3. 暂时不做自动爬取热点；
4. 暂时不做自动发布；
5. 暂时不做多用户权限；
6. 暂时不做复杂后台管理。

第一版重点是跑通最小闭环：

> 页面输入 → AI 生成 → 页面展示 → 部署上线 → 家人试用

## 7. 输入字段

输入字段指的是：用户在网页表单里需要填写或选择的内容。  
这些字段会作为 AI 生成内容方案的依据。

### 7.1 目标客群

说明：这次内容主要想吸引哪一类游客。

可填写示例：

1. 亲子家庭；
2. 情侣游客；
3. 大学生；
4. 公司团建；
5. 带父母出游；
6. 周末短途游游客；
7. 暑假避暑游客；
8. 河南周边自驾游客。

页面形式建议：

- 第一版可以用文本输入框；
- 后续可以改成下拉选择。
### 7.2 民宿卖点

说明：这次内容想重点展示白格美宿的哪些优势。

可填写示例：

离重渡沟景区近；
停车方便；
适合带孩子；
适合带父母；
房间干净；
环境安静；
夏天凉快，适合避暑；
可以吃家常饭；
适合自驾游；
老板服务热情。

页面形式建议：

第一版可以用多行文本框；
用户可以一次输入多个卖点。

示例输入：

停车方便，房间干净，离重渡沟景区近，适合带孩子避暑
### 7.3 当前热点

说明：最近有什么节假日、旅游趋势、平台热点或者游客关心的话题。

可填写示例：

暑假避暑；
五一出游；
十一假期；
河南周边游；
洛阳旅游；
带娃出游；
带父母旅行；
周末短途游；
重渡沟避暑；
自驾游攻略。

页面形式建议：

第一版用文本输入框；
用户可以手动从抖音、小红书、评论区复制热点词。

示例输入：

暑假避暑，河南周边亲子游
### 7.4 发布平台

说明：这条内容准备发布到哪个平台。不同平台的文案风格不同。

可选择示例：

抖音；
小红书；
朋友圈；
视频号。

页面形式建议：

第一版用下拉选择框；
默认可以选择“抖音”。

示例输入：

抖音
### 8. 输出内容

输出内容指的是：用户点击生成后，AI 返回给用户看的结果。
第一版输出 4 类内容。

### 8.1 标题建议

说明：AI 根据客群、卖点、热点和平台，生成适合发布的标题。

输出要求：

生成 5 条标题；
标题要适合真实游客；
不要太夸张；
不要像硬广告；
要突出游客关心的问题。

示例输出：

1. 夏天带孩子来重渡沟避暑，这家民宿真的省心
2. 洛阳周边亲子游，不想折腾可以看看重渡沟
3. 带父母来重渡沟，住得舒服比打卡更重要
4. 河南周边避暑游，重渡沟这家民宿适合一家人
5. 自驾来重渡沟，停车方便真的太重要了
8.2 短视频脚本

说明：AI 生成一条适合拍摄的短视频脚本。

输出要求：

包含开头 3 秒怎么说；
包含中间展示哪些内容；
包含结尾如何引导咨询；
语言要自然，不能太像广告；
家人拿着手机就能照着拍。

示例输出：

开头 3 秒：
“夏天想带孩子来栾川避暑，但又怕住宿不方便，可以看看重渡沟这家民宿。”

中间内容：
先拍民宿门口和周边环境，再拍停车位置，接着展示房间卫生、床品和窗外环境，最后拍一下孩子可以活动的空间和附近景区路线。

结尾引导：
“准备暑假来重渡沟的朋友，可以提前问问房型和日期，旺季建议早点订。”
8.3 镜头清单

说明：AI 告诉家人具体要拍哪些画面。

输出要求：

镜头要具体；
不需要专业设备；
手机就能拍；
每个镜头最好说明拍摄重点；
镜头要围绕游客关心的问题。

示例输出：

1. 民宿门口全景：展示整体环境，让游客知道到店第一眼是什么样。
2. 停车位置：突出自驾游客最关心的停车方便问题。
3. 房间床品：拍床、被子、枕头，突出干净整洁。
4. 卫生间：简单展示卫生情况，增加信任感。
5. 周边山景：突出重渡沟夏天凉快、适合避暑。
6. 小朋友活动画面：突出亲子友好。
7. 到景区路线或门口方向：让游客知道位置方便。
8. 家常饭菜：展示入住后的生活感和烟火气。
8.4 朋友圈文案

说明：AI 生成一条可以直接发朋友圈的文案。

输出要求：

语气自然；
不要太营销；
像真实民宿老板发的内容；
可以带一点温度；
适合配图片或短视频。

示例输出：

夏天来重渡沟，很多客人最关心的其实不是玩多少景点，而是住得舒不舒服、停车方不方便、带孩子累不累。

白格美宿这边离景区近，自驾停车也方便，房间每天都会认真打扫。带孩子、带父母过来避暑的朋友，可以提前看看房型和日期。

山里晚上很凉快，适合一家人慢慢住两天。
9. 页面结构设计

第一版页面不追求复杂和美观，重点是清晰、好用、能跑通。

页面结构如下：

页面标题：
白格美宿内容方案生成器

页面说明：
输入客群、卖点、热点和发布平台，AI 自动生成适合发布的内容方案。

输入区域：
1. 目标客群
2. 民宿卖点
3. 当前热点
4. 发布平台

按钮：
生成内容方案

输出区域：
1. 标题建议
2. 短视频脚本
3. 镜头清单
4. 朋友圈文案
10. 用户使用流程
第 1 步：打开网页
第 2 步：填写目标客群
第 3 步：填写民宿卖点
第 4 步：填写当前热点
第 5 步：选择发布平台
第 6 步：点击生成内容方案
第 7 步：复制标题、脚本、镜头清单或朋友圈文案
第 8 步：家人根据镜头清单拍摄并发布
11. 技术方案
11.1 前端和页面

使用 Streamlit 快速搭建网页页面。

选择原因：

开发速度快；
适合新手快速做 AI 工具；
不需要复杂前端基础；
可以快速部署上线；
适合第一阶段验证产品价值。
11.2 AI 模型调用

第一版可以选择以下任意一种模型 API：

OpenAI API；
DeepSeek API；
通义千问 API；
豆包 API。

第一版重点不是比较模型强弱，而是先掌握：

用户输入 → 构造 Prompt → 调用 AI → 返回结果 → 页面展示
11.3 数据存储

v0.1 暂时不做数据存储。

原因：

第一周重点是跑通生成和部署；
避免一开始复杂度过高；
数据记录功能放到 v0.2；
先验证家人是否真的愿意用。
11.4 部署方案

可选部署平台：

Streamlit Cloud；
Render；
Railway；
云服务器。

第一版推荐优先使用 Streamlit Cloud 或 Render。

13. Prompt 设计要求

AI 生成内容时，必须遵守以下原则：

内容必须服务白格美宿真实经营；
不能生成过度夸张、虚假承诺的文案；
语言要像真实民宿老板或普通游客能接受的表达；
镜头清单必须具体，可执行；
内容要围绕游客真实关心的问题；
不要只写空泛形容词，例如“环境优美”“服务一流”；
要尽量体现重渡沟、栾川、避暑、亲子、自驾等场景；
输出结构必须清晰，方便复制使用。
14. 成功标准

v0.1 项目成功的标准不是代码多复杂，而是是否完成真实闭环。

14.1 技术成功标准
本地可以正常运行；
页面可以正常输入信息；
点击按钮后可以调用 AI；
AI 可以返回结构化内容；
项目可以部署上线；
家人可以通过链接访问；
API Key 没有泄露到 GitHub。
14.2 业务成功标准
家人能看懂页面怎么用；
家人能独立生成一次内容方案；
生成内容中至少有一部分可以直接使用；
镜头清单能指导家人实际拍摄；
家人愿意再次使用这个工具；
工具确实减少了“不知道发什么”的问题。
14.3 学习成功标准
我理解了一个 AI 应用的基本开发流程；
我掌握了 Streamlit 的基础使用；
我掌握了 AI API 的基础调用方式；
我知道如何用环境变量保护 API Key；
我完成了第一次项目部署；
我有了一个可以写进简历的真实项目雏形。

16. 后续版本规划
v0.2 内容记录表

加入内容保存功能，记录每次生成的选题、平台、是否采用、发布时间和基础数据。

计划字段包括：

内容标题；
发布平台；
是否采用；
发布时间；
播放量；
点赞量；
收藏量；
评论量；
私信咨询量。
v0.3 每周复盘建议

根据一周内容数据，自动生成经营复盘建议。

计划功能包括：

统计表现最好的内容；
分析哪个客群更有反馈；
总结哪些卖点更有效；
输出下周内容建议；
输出具体拍摄任务。
v0.4 热点筛选器

支持用户手动粘贴热点，由 AI 判断哪些热点适合白格美宿。

计划功能包括：

粘贴热点内容；
AI 自动分类热点；
判断是否适合白格美宿；
推荐 5 个最适合拍摄的选题；
生成对应内容方案。
### 17 当前版本不做的事情

为了保证第一周可以完成，v0.1 暂时不做以下内容：

不做登录注册；
不做复杂数据库；
不做自动爬取热点；
不做自动发布到抖音或小红书；
不做复杂权限系统；
不做付费系统；
不做多商家管理；
不做复杂数据看板。

当前阶段最重要的是：

先做出一个家人能打开、能输入、能生成、能看懂、愿意试用的小工具。
